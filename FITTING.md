# MPFIT fitting

The fit dialog supports **one peak** with three shapes ported from the previous Objective-C analyzer (`objFit.m`): Gaussian + constant, exponential–Gaussian hybrid (EGH), and dual exponential Gaussian (DEG). Multiple peaks and linear backgrounds are not implemented. Drift fitting continues to use Gaussian + constant.

## Peak models

With `d = x − center`, height `A`, and Gaussian-core standard deviation `sigma`:

- **Gaussian + constant:** `background + A exp(−d² / (2 sigma²))`.
- **EGH:** `A exp(−d² / (2 sigma² − lambda d))` when the denominator is positive, otherwise zero. This is the legacy `EGH`/`expGaussfuncM` model, not an exponentially modified Gaussian convolution. The signed decay parameter `lambda` is in µs; negative values extend the right tail and positive values extend the left tail. Zero gives a Gaussian with zero background.
- **DEG:** a Gaussian core for `−leftSwitching ≤ d ≤ rightSwitching`, a left tail `A exp(leftSwitching (leftSwitching + 2d) / (2 sigma²))`, and a right tail `A exp(rightSwitching (rightSwitching − 2d) / (2 sigma²))`. Both positive switchover distances are in µs relative to the center. Value and first derivative are continuous at each junction. Smaller distances give longer tails.

EGH and DEG have no background term, matching the legacy model equations. All time parameters and uncertainties use µs. The Gaussian model displays FWHM; EGH and DEG display **Gaussian σ** directly in µs, including its absolute uncertainty. Switching between Gaussian and asymmetric models converts both width and uncertainty using `FWHM = 2 sqrt(2 ln 2) sigma`. For saved results, Gaussian FWHM is `2 sqrt(2 ln 2) sigma` above the constant background. EGH and DEG FWHM is measured by tracing the full fitted function to its left and right half-maximum crossings, including crossings outside the ROI. The trace brackets and bisects each crossing in coordinates relative to the peak center and normalized by sigma. Saved rows use the full-precision fitted width, not the rounded sigma input. Hybrid FWHM uncertainty propagates all width/shape parameters and their covariance; it is not simply sigma's uncertainty times a Gaussian factor. The bottom results table also recalculates widths for existing saved fits when their model and complete fitted shape parameters are available; older records without those parameters retain their stored width. The full fit result records its model and width convention. Model changes invalidate previews and preserve entered parameters and fixed/free settings. Inactive parameters are excluded from validation and fitting.

The model equations are preserved, but the old optimizer's statistical treatment is not reproduced: the legacy fits removed empty bins and DEG used a different residual expression. All three shapes here use the weighted least-squares convention below, including empty bins. Consequently numerical optima, chi-square, degrees of freedom, and uncertainties can differ from the previous app.

## Build and run

On the build machine, with Node.js development headers and C/C++ build tools installed:

```
npm run build:native
npm test
npm start
```

The build compiles the existing mpfit.c source and native/fitaddon.cc into build/Release/fitaddon.node. The old mpfit.o is not used. On this Mac the build uses the local Node.js headers and requires no download. NODE_HEADERS_DIR can identify another Node installation prefix containing include/node/node_api.h. Without local headers node-gyp may need to download headers; prepare these on the connected build machine.

The addon uses only Node-API version 8. This avoids direct V8 bindings and reduces Node/Electron ABI coupling. A compiled binary is still specific to operating system and CPU architecture. Stage and test a build for every deployment target. The current build has been tested under Node.js on macOS arm64; Electron runtime loading has not yet been tested because this checkout has no installed Electron runtime or window launcher. Package the .node file outside ASAR when building the Electron application.

For air-gapped operation, transfer the app, installed dependencies, and the matching native binary. Running fits does not download anything and requires no compiler. Do not assume an arbitrary node_modules folder or native binary from another operating system will work.

## Use

Load a listmode file, display the peak, set an ROI using the plot's right-click menu, and choose Fit ROI. Select the model and enter the initial absolute center (µs), width (FWHM for Gaussian, Gaussian σ for EGH/DEG, in µs), height, and the model-specific background, decay, or left/right switchover parameters. All fit parameters use value(uncertainty), for example 123(2.1), meaning 123 ± 2.1 in the same units. Right-click the center cell or another parameter column to select Fixed: a nonzero uncertainty constrains that parameter to the entered value ± uncertainty; (0) holds it exactly. Free parameters ignore the entered uncertainty as a bound. (?) denotes an unavailable uncertainty and must be replaced before selecting Fixed. Requested bounds intersect the physical/model bounds (nonnegative background/height, positive width, center inside the ROI). Run Fit overwrites all parameter inputs with the fitted values and 1σ uncertainties, rounded to two significant uncertainty digits; exact holds show (0). A parameter that hits a bound can display (?) instead of a misleading uncertainty. The next run uses the displayed values and uncertainties. Fill Ion, q, and Laps to save the fit; ΔToF stores the center uncertainty, and the saved fit retains its complete result including covariance and FWHM uncertainty.

A fit worker keeps the server responsive and is terminated after 15 seconds. Editing fit parameters invalidates the previous preview so it cannot be saved as a fit to the new inputs. Valid changes turn yellow; invalid entries turn red. Run Fit validates every active parameter and shows one error alert listing invalid fields without submitting a request. Reverting an edit clears its yellow highlight, and a successful fit resets the edited markers. Scientific notation is accepted; negative uncertainties, nonnumeric text, nonpositive width, and negative center/height/background values are rejected. Unknown uncertainty (?) is allowed only for a free parameter.

## Statistical interpretation

The residual is (observed count − model count) / sqrt(max(observed count, 1)). Empty bins are retained. This is an approximate weighted least-squares treatment of count data, not a Poisson maximum-likelihood fit. Covariance and 1σ errors come from MPFIT and are **not multiplied by sqrt(reduced chi-square)**. The returned `covarianceOrder` identifies each row/column: Gaussian uses baseline, sigma, amplitude, center; EGH uses decay, sigma, amplitude, center; DEG uses rightSwitching, leftSwitching, sigma, amplitude, center. Units correspond to the returned parameters, with time parameters in µs.

Free widths and amplitudes must be positive/nonnegative and centers lie inside the ROI. A free parameter at a bound or a singular/ill-conditioned covariance suppresses uncertainty reporting. The covariance check uses the free-parameter correlation matrix, so it is independent of parameter units; eigenvalues below 1e-10 of the largest are treated as unresolved. MPFIT convergence and a small reduced chi-square do not establish that parameters can be determined independently. In particular, coarse DEG bins can sample only the exponential tails and leave the Gaussian core unresolved; the dialog reports this explicitly and suggests finer bins, known shape constraints, or a simpler model. Unavailable errors display as (?) while preserving the fitted central values. Even for finite large errors, display rounding never erases the value when its uncertainty is as large as the value. Large reduced chi-square is shown as a model-quality warning. The included sample peak has an asymmetric tail, so a symmetric Gaussian over a broad ROI can fit poorly even when numerical convergence succeeds. Do not interpret convergence alone as a good physical model.

## Custom models

The native addon exports fit(options, residualFunction). residualFunction receives the complete parameter array and returns one finite residual per data bin. Peak equations are in public/js/fit-models.js; fit-engine.js handles scaling, constraints, and covariance. The HTTP endpoint accepts the three named models (`gaussianConstant`, `exponentialGaussianHybrid`, `dualExpGaussian`), not arbitrary executable function text.

## Drift fitting

Drift Correct is enabled after a complete, nonempty fit ROI is set on a loaded spectrum. A modal dialog first asks for a positive whole-number tranche size, defaulting to 5,000 sweeps; Cancel or Escape starts no run. It fits the selected TAG, channel, and edge in successive tranches of that size over the active sweep range (or the full run). The last partial tranche is included. Each tranche uses independent automatic initial guesses and a free Gaussian + constant model; it does not inherit the manual fit dialog's parameter constraints. The TOF ROI and settings are a snapshot at the time the button is clicked.

A movable, resizable, non-modal window shows relative fitted center versus sweep with 1σ errors, and a table containing center, FWHM, counts, reduced χ², and warnings or failures for every tranche. Orange points have quality warnings; open circles lack a reported uncertainty. After the fits finish, a derived drift-corrected spectrum is added to the spectra list. Successful tranches retain all events, including all TAG numbers and channels and events outside the fitting ROI and plot range. The first successful tranche is the reference and is unchanged; failed initial tranches are discarded. Each later tranche’s full recorded TOFs are multiplied by first/current absolute fitted center. Every event in a failed later tranche is discarded, across all TAG numbers, channels and edges. Empty tranches are skipped during fitting. A tranche with no events across the full spectrum is treated as a gap and resets the consecutive-failure count; it is not counted as a failed fit. An empty fitting ROI in a tranche containing other events still counts as a failed fit, and those events are discarded. More than 32,768 sweeps in consecutive failed tranches aborts the entire correction, without creating a derived dataset. Exactly 32,768 is allowed; a successful fit resets the consecutive-failure count, and partial tranches contribute their actual sweep span. Events outside the fitted sweep range stay unchanged and are reported. If no tranche succeeds, no corrected spectrum is created because no reference exists. The original dataset is preserved. Double-click the derived entry to display it. Repeated completion messages for the same fit run do not create duplicates. Close the results window to cancel an in-progress request. Runs have a 60-second time limit.

Combined spectra place each source on a shared sweep timeline using its acquisition start time. In `cmline3`, `MP:` specifies the master period for two alternating-TAG sweeps, so the recorded sweep period is `MP / 2`; legacy `P:` already specifies one sweep's period. For example, `MP:50000` means 25,000 µs per sweep (40 sweeps/s). Offsets are rounded to the nearest recorded sweep and acquisition gaps remain empty.
